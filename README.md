# 项目需求与设计 Skill

按当前问题开展需求、模型、架构、交互或任务与验收分析。先形成能支持当前决定的结论，再随实际用途增加细节；不绑定技术栈、设计工具或固定产物清单。

入口为 [SKILL.md](SKILL.md)。技能源码、安装副本与业务材料分别管理，业务产物不写入技能包。

## 分析路径与能力

| 当前问题 | 能力 |
|---|---|
| 目标、场景与范围 | [需求探索](references/stages/discovery.md)，按需做价值与可行性判断 |
| 概念、关系、状态与数据 | [领域与数据模型](references/stages/modeling.md) |
| 实现机制、技术比较与 demo | [技术架构与验证](references/stages/architecture.md) |
| 任务路径、页面、反馈与恢复 | [交互与 UI 设计](references/stages/interaction.md) |
| 交付切片、执行任务与验收 | [任务拆分](references/stages/issue-delivery.md) |
| 有效结论发生变化 | [变更分析](references/changes/impact.md) |

这些能力可独立进入；五阶段称呼用于兼容已有项目，不是必经顺序。完整项目可以逐步往返完善，局部请求到本轮目的完成即可。详细规格、追溯与正式交接检查只在当前用途需要时增加。

## 使用

```text
$project-design 帮我分析当前项目，本轮先明确目标和首期范围。已有资料位于……
```

也可以直接提出“只比较这两种路径”“设计文件导入模块”“改善这个页面的失败恢复”或“细化撤销订单的验收条件”。先复用相关现状和有效决定，缺少的关键业务事实集中处理。

技能尚未被宿主发现时，可明确要求读取实际入口。文件存在、手动读取成功与自动选择是不同状态；纯代码修复、部署执行和技能维护不启动业务分析。

## 文档怎样组织

**默认直接更新已有主题，附加记录需要有具体用途。** 普通咨询在对话交付；单次保存无需创建项目配置、辅助目录、来源表、决策表、变更表、交接或评审报告。

- 关键理由、依据、未知和简短检查结论可以放在原文或任务的小节中。需要长期解释重大取舍、恢复中断工作或复现实验时，再复用已有记录；现有位置无法承载才独立保存。
- 业务规则只在一处完整维护，其他设计和任务用必要摘要、责任说明与具体引用关联。复杂度和独立维护责任决定是否拆专题，内容性质不直接决定文件数量。
- 普通变更使用 Git／平台历史，沿用已有 ID；固定交接或关系较多时才增加版本标识、稳定编号和覆盖表。避免同一事项分别写入来源、决策、变更、交接和评审。
- 默认回读自检。用户／项目要求独立评审，或复杂交接、重大变更需要额外把关时才安排；没有独立评审不影响普通任务完成。简短结果留在交付说明或任务里，有实质整改或留证要求才另存报告。
- 项目现有目录、命名和配置继续有效。没有配置也可以保存；确需共享长期导航时再使用 `.project-context.json`，已有扩展字段和双向交接入口保持兼容。

详细条件见 [文档规则](references/shared/document-structure.md)、[项目上下文](references/shared/project-context.md) 与 [工作约定](references/shared/working-contract.md)。原型、运行验证与实际交付分别按真实范围报告。

已有辅助材料不随升级自动清理。用户要求整理时，按当前用途、引用、恢复和复现价值判断保留、合并或清理；不能按目录名批量删除，也不要把所有过程合并成不断增长的总日志。项目 `AGENTS.md` 已明确的评审、分区与留证要求仍需遵守，技能更新不会自动改写项目规则。

## 安装与更新

仓库：[FarmerLi/project-design-skill](https://github.com/FarmerLi/project-design-skill)。技能名称和安装目录名均为 `project-design`。

```text
请读取 https://github.com/FarmerLi/project-design-skill 仓库中的《installation.md》，将 project-design 安装到当前项目；已有安装则更新到最新正式版。请按指引完成版本检查、必要的整包下载、备份替换和安装校验，并报告版本与安装位置。
```

默认安装到目标项目 `.agents/skills/project-design/`，个人全局、固定 Tag 或开发分支按实际请求选择。完整流程见 [安装与更新](installation.md)。

旧文档、编号和配置按有效内容复用；升级不自动迁移业务项目、重建任务或覆盖项目规则。

## 技能包的维护分工

`SKILL.md` 维护默认行为和能力入口；`references/stages/` 只展开能力方法；`references/shared/` 维护按用途启用的公共规则；`selection/`、`entry/`、`changes/`、`integrations/` 分别提供选型、现状、变更及实际保存方法。示例用于校准深度，不作为项目事实。

`tests/` 提供行为场景和实际记录，不是运行依赖；`maintenance/archive/` 保存历史维护材料，不参与当前规则。修改时检查格式、引用与受影响的 [行为用例](tests/behavior-validation.md)，分别报告静态检查和实际执行结果；历史记录不证明新版本已经验证。

## 技能文档命名

技能包文档、模板与验证说明使用英文 kebab-case 文件名，标题和正文使用中文；保留 `SKILL.md`、`README.md` 等固定入口。业务产物仍沿项目约定命名，未约定时使用中文文件名；改名同步当前引用，不重写历史证据。
