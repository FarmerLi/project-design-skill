# 项目交付配置

有本地项目目录时使用文件名 `项目上下文.md`，放在被分析项目根目录；纯远端项目可将内容作为已授权项目页面或父项中的“项目上下文”章节。配置后续任务拆解和文档维护的目标、规则与关联方式。已知项直接填入，未知项按需补充；不保存密码或令牌。

## 项目

| 配置 | 值 |
|---|---|
| 项目名称／代号 | 未确认 |
| 项目根目录／代码仓库 | 未确认；纯远端且无本地目录／仓库时说明实际情况 |
| 配置维护位置与路径基准 | 本地文件路径或远端页面／父项 URL、ID 及章节；本地相对路径的基准目录 |

## 任务管理系统

| 配置 | 值 |
|---|---|
| 目标系统 | 未确认；例如 Jira；不用远端时写“本地按故事维护” |
| 实例地址与项目 | 未确认；例如实例 URL 与项目 key |
| 任务类型与层级 | 未确认；按目标项目实际配置填写，不预设 Epic／Story／Sub-task |
| 默认关联父项 | 未确认；按需求选择或明确无默认父项 |
| 任务内容约定 | 故事的本次目标、详细行为、验收条件及可执行研发测试任务；任务包含范围、输入输出、依赖、完成判据与证据，测试含数据／环境、步骤和预期 |
| 负责人、优先级、版本等默认值 | 未确认；没有约定不推测 |
| 执行约定 | 默认在用户要求创建／同步任务时执行；如用户已明确授权自动落地，记录适用范围和依据 |
| 已有任务关联记录位置 | 未确认；保存需求／场景／故事 ID、验收条件与研发测试任务 key／URL 的对应关系 |

## 需求文档维护

| 配置 | 值 |
|---|---|
| 正式维护位置 | 未确认；本地目录／Notion／Confluence／其他，选择实际主位置 |
| 本地目标 | 未确认；使用本地时填写目录或已有文件 |
| Notion 目标 | 未确认；使用时填写工作区及父页面／数据库链接或 ID |
| Confluence 目标 | 未确认；使用时填写站点、space key 和父页面／已有页面链接或 ID |
| 文档组织方式 | 共享需求／设计沿用已有结构；本地维护故事时每故事独立文档，总览保留索引和批次；任务系统维护故事时记录实际链接，不重复正文 |
| 已有文档与维护范围 | 未确认；指定已有文档及可更新章节，避免每次重新创建 |
| 保存方式 | 默认更新关联的已有文档；无关联时按目标组织方式新建 |
| 执行约定 | 记录用户是否要求阶段结果直接写回正式位置，或先保留草稿；仅填写地址不视为发布授权 |
| 本地草稿／工作状态目录 | 有本地项目目录时默认 docs/project-analysis/；纯远端可写“不保留本地草稿”，状态与交接保存在指定远端位置 |
| 项目概览／决策／交接位置 | 沿用目标项目实际文件或远端页面位置；首次使用时按需要建立 |

只保留选中平台的配置行。不同时维护多套正文，除非明确要求并约定同步方向。

## 任务与文档关联

| 配置 | 值 |
|---|---|
| 需求正文的正式来源 | 上面指定的正式维护位置；有例外则填写 |
| 任务执行状态的正式来源 | 上面指定的任务管理系统；有例外则填写 |
| 故事／AC／任务正文的正式来源 | 任务系统或本地故事文档，选择唯一主位置；本地默认 docs/project-analysis/stories/用户故事-编号-主题.md |
| 关联方式 | 研发测试任务引用需求文档、故事 ID 及验收条件；文档记录相关任务 key／URL 和结果证据 |
| 草稿与远端版本的关系 | 未确认；例如远端为正式版本、本地仅作待发布草稿 |

配置依据：填写用户说明或已有项目约定。
最近核实日期：未确认。
待补充信息：按当前动作需要列出。
