# 本体设计适配器

仅在明确选择或评估本体设计时加载。读取 [交接契约](../shared/working-contract.md) 和 [适配器契约](../adapters/catalog.md)。

## 先确认元规范

“本体驱动”不唯一对应某套元规范。优先使用用户已指定的规范、路径和版本；本包不内置特定元模型。未指定时先根据目标说明需要什么表达能力，再比较实际可用的规范，不默认选择参考项目的方法。

未选元规范时，可以形成概念关系与模型候选，但不能声称生成了符合特定 schema 的 YAML。需要正式模型而元规范缺失时，明确所需资料；不猜测字段和校验规则。

用户选定外部规范时，读取其原文作为格式依据，不自动执行外部技能的整套开发流程。记录实际获取的版本、提交号或获取日期；取不到原文则只交付映射草案。规范与示例冲突时记录双方位置及差异，不能用示例覆盖已确认需求。

## 适配步骤

1. 从 [设计输入](../shared/design-input.md) 引用有效概念、关系、操作、规则、协作及相关约束；每个模型元素保留需求／场景来源。模型阶段不重新发明业务定义。
2. 检查需求是否超出所选规范的表达能力，尤其外部接口、异步过程、质量目标、数据访问范围和交互约束。输出明确的不匹配清单。
3. 对不匹配项提出扩展规范、配套规格或更换方法的选项。方案尚未确定时保留业务需求和阻塞，不静默改成框架支持的行为。
4. 按选定规范组织模型与引用；发现业务定义矛盾返回需求阶段。
5. 核对 ID 唯一、引用有效、模型与场景结果一致。具体一对一规则、流程图约束等只在选定规范要求时执行。

## 输出

交付以下适用内容；需要保存时按项目配置维护，本地默认放入 `design/ontology/`，临时咨询不强制建文件：

- `本体映射.md`：采用规范、需求版本、业务到模型映射、覆盖情况；
- `缺口记录.md`：仅在存在缺口时建立，说明不支持项及处理决策；
- 模型文件：仅在格式依据充分且本轮确实需要时生成。

质量要求、部署约束、接口契约等可以保持为独立规格，并建立引用；不因模型未覆盖就删除。
没有执行解析／schema 校验时明确标记为人工语义核对，不能报告机器校验通过。对规范作了扩展就注明扩展版，不冒充原版兼容。

本适配器不选择技术底座，不强制 AI 助手或固定 UI，也不把“一次业务操作”固定解释为某种事务实现。
