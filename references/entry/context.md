# 入口识别、现状与恢复

用于分析入口不明、已有项目需要了解现状或恢复工作。目标与直接材料已明确时进入对应能力即可。

## 选择最短有效路径

| 本轮目的 | 先做什么 |
|---|---|
| 新项目目标或范围 | 从用户问题进入 [需求探索](../stages/discovery.md) |
| 已有产品新增能力 | 核对相关现状与目标差距，只补本轮范围 |
| 技术方案或关键 demo | 找相关链路、约束和待验证命题，进入 [架构与验证](../stages/architecture.md) |
| 概念、数据或演进问题 | 进入 [模型设计](../stages/modeling.md) |
| 用户任务与反馈 | 进入 [交互设计](../stages/interaction.md) |
| 故事、任务或进展 | 进入 [交付切片](../stages/issue-delivery.md) |
| 改变有效结论 | 明确差异，再做 [变更分析](../changes/impact.md) |

## 有边界地了解现状

先读指定材料、当前任务及直接相关正文。具体问题需要时才沿相关代码或运行证据取证；信息足以支持当前决定即停止扩读。

区分实际观察、有效约定与本次目标，文档与代码冲突时保留差异并核对依据。未知可以支持条件性探索，不能润色为既有能力或业务规则。技术环境属于现状，不自动代表必须沿用。

相关现状优先写在当前主题，只有会反复复用且需要独立维护时才建专题。

## 恢复

从当前任务及引用进入；入口分散时读取已有 [项目上下文](../shared/project-context.md)，实际进展不清时再补相关交接。没有配置或交接则核对当前正文和代码，不为恢复先补建档案。

过期交接不能覆盖有效结论，历史结果不自动证明当前版本通过。恢复缺口只阻塞依赖部分，必要的下一步更新到已有任务／记录，详见 [工作约定](../shared/working-contract.md#每轮恢复与保存)。
