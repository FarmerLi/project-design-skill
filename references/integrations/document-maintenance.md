# 需求与设计文档维护

将本轮有效结论归并到唯一维护位置，同时处理内容归属、层次、引用与中间材料。先按 [项目配置](../shared/project-context.md) 确定目标、更新范围和既有保存授权，再遵循 [文档结构规范](../shared/document-structure.md)。临时咨询在对话交付，不执行落盘；局部任务只维护合理相关范围。

## 定位正文与辅助区域

| 目标 | 定位方式 |
|---|---|
| 本地 | 读取现有文档及实际目录；无约定时，正文在 `docs/project-analysis/`，辅助材料在相邻的 `docs/project-analysis-support/` 分区 |
| Notion／Confluence／其他远端 | 按实际父页面、数据库、空间及已有 ID／链接读取当前结构和版本；正文页与交接、来源、验证、附件等辅助页面分组 |

只使用本次目标需要且实际可用的工具／技能。没有本地目录时直接从已授权远端目标开始，不先创建本地副本。远端为正式来源时，本地仅保留已约定的草稿或索引，不维护另一份正式正文。

## 归并、整理并保存

1. **读取当前内容及引用。** 定位本次主题、共享定义、相关相邻专题和版本；不仅沿已有链接读取，也按术语及别名查找可能未互链的同义主题。保护其他人的无关内容，发生并发变化先核对，不以整页覆盖规避合并。大幅重组且无可恢复历史时，在辅助归档区保存必要快照。
2. **分类并确定责任。** 同一输入拆出需求、模型、实现、来源、工作过程和运行证据。按 [主题边界与唯一维护位置](../shared/document-structure.md#主题边界与唯一维护位置) 确定各篇分工、每项定义的权威章节及引用用途，再决定归并或拆分；不按提问次序、阶段或当前评审组件归类全部内容。
3. **重建阅读主线。** 先写对象、范围、整体结论／方案与关键关系，再由主题专题展开。专题也先说明整体关系再深入；细节过深且有独立维护责任时继续拆子专题。父文保留必要概貌和入口，不只剩链接，也不复制全部细节。
4. **整合有效正文。** 直接陈述行为、机制及成立条件，移出会话转述、确认经过、委托与工具记录。跨文档按语义归并重复，保留独有有效条件；其他位置改为有明确用途的摘要／应用及引用，冲突按有效依据处理。处理旧范围和已解决问题；有效选择融入方案，仍影响实施的未决项写清具体缺口与阻塞。系统运行算法属于设计，实际测试步骤与输出属于证据。
5. **分区并清理材料。** 交接、来源、决策、变更、验证和附件放独立辅助区域；已整合且无保留价值的临时草稿在本次维护范围内删除，必要证据及有价值历史分别保存。既有文件先查用途、内容和引用，不能按文件名直接删除，也不把所有临时文件永久归档。
6. **维护变化与引用。** 按 [版本约定](../shared/working-contract.md#版本完成标准与变更) 区分等价编辑、语义变更、基线与证据变化。同步配置、主文摘要、专题索引、图源／图片和任务链接；未复核下游保留实际输入及“需复核”。迁移后只有一份当前正文。
7. **保存并独立评审。** 按已有授权保存并核实结果；失败或不明先查询再重试。固定该版本，按 [交付前阅读评审](../shared/document-structure.md#交付前的阅读检查) 交给未参与编写、且不继承主会话历史的子 Agent，只读当前正文与必要引用，检查层次、责任、当前结论、图文一致、材料分区及清理结果。主 Agent 处理意见并按需复评，记录实际路径／ID／URL、受审版本、结果及未检查项；自检不替代独立评审。

仅有地址不等于发布或写回授权；先完成具体可审阅内容，只有真正阻塞的目标或授权缺口才需要澄清。已有持续维护授权直接沿用。保存成功只证明写入，不代替内容就绪或运行验证。

## 关联故事、任务与交接

按 [第四阶段维护规则](../stages/delivery.md#保存与任务落地) 保存故事：本地每故事独立文档，已有满足同等深度的单故事场景可复用；总览维护目标、需求边界、索引、批次及依赖。多个故事混在总表中时拆分有效正文，保留稳定 ID 及承接关系。

任务系统为正式来源时，在系统维护完整故事、AC、研发测试任务和依赖；本地或其他文档平台只保留必要索引及共享设计，不复制故事正文。维护任务另读 [任务落地](task-tracking.md)。

恢复工作所需的已做动作、执行边界和下一步写入独立辅助交接，正式概览只保留当前项目状态与阅读入口。未执行的工作、失败及尚未写回项如实记录；工具不可用时保留约定草稿或在对话交付，不擅自切换正式来源。
