# 子代理启用与任务分配

用于实际委派勘察、设计切片或独立阅读时；简单讨论由主 agent 直接完成。主 agent 负责有效需求、范围取舍、共享定义、跨主题整合和交付判断。父 Issue／sub-issue 表达工作范围与验收，agent 表达本轮执行分工，两者不一一对应，也不按五阶段各开一个 agent。

## 按收益与依赖启用

| 辅助任务 | 适合委派的条件 | 返回结果 |
|---|---|---|
| 材料勘察／问题调研 | 需要较多独立阅读，问题和停止条件明确 | 带出处的事实、适用版本、候选与缺口；不代定业务取舍 |
| 有边界的设计或交付切片 | 必要输入已明确，主题／写入责任可分开，返回后能够独立核对 | 指定主题的设计或任务草稿、来源与验收映射、变化影响及未决项 |
| 独立阅读评审 | 当前交付已形成稳定版本，按[阅读评审规则](document-structure.md#交付前的阅读检查)核对 | 对当前正文及必要引用的理解、实质问题及证据；不参与编写受审版本 |

共享规则未定、频繁依赖同一中间状态或只能修改同一正文的工作由主 agent 收敛后顺序推进；子 Issue 已建立不代表依赖已就绪。共享前置只由一个责任方处理，消费者在有效结果可用后继续。可委派收益不足时不启动额外代理；独立阅读仍按原规则执行，不能用少开代理为由省略必需评审。

本技能只委派当前已授权的分析／设计工作，不因 Issue 可执行而自动启动产品编码。实际开发交接由项目流程承接，不把任务拆分当作编码、测试、发布或远端写入授权。

## 最小任务输入与写入归属

委派提供本次问题或交付结果、完成判据、排除范围、有效来源及版本、适用规范章节、依赖状态、实际工作路径／基线、允许的动作和返回形式。采用 Issue 时给出具体执行项及分配条目；父项只补必要目标、整体约束和覆盖关系，汇总项不能作为含糊的整包执行指令。没有任务系统时沿用当前有效材料，不为委派新建 Issue。

只传必要原始材料与定位，不复制整个父项、全部子项或主会话历史；子 agent 可沿直接相关引用核实依据，缺失时报告，不用摘要替代关键规则。独立阅读的上下文隔离与输入边界统一按上述评审规则，不向评审者提供预期结论。

同一工作区只有一个写入方；并行编写使用独立工作区或等效隔离，并明确共享文件由谁整合。只读勘察可以并行，输入变化时须记录影响；评审固定受审状态。子 agent 不自行改动其他责任方的规范正文、提交合并、创建／关闭远端任务；确需外部动作须有明确分配及原有授权。默认不递归委派，新增分工由主 agent 统一协调。

## 变化、返回与整合

父范围、子项映射、规则或依赖发生有效变化时，主 agent 更新任务依据并通知受影响执行者；停止旧方案写入、核实命令与实际差异后再分配，未受影响工作可继续。取消代理不等于取消 Issue，代理结束也不等于 Issue 关闭。

返回实际产物位置与版本、所分配条目的覆盖、依据和验证、未完成项及跨主题影响。分离工作区的内容由主 agent 显式整合，同一工作区顺序交接不重复应用改动。主 agent 回读整合结果，核对父目标到子项的覆盖、共享定义和跨项验收，再按交付规则判断完成；不能相加各代理的通过声明代替整体证据。工作状态沿实际任务来源维护，不建立第二套实时台账。

宿主没有委派或隔离能力时，由主 agent 完成可执行部分，如实标记缺少的独立评审；不擅自安装代理框架、外发材料或伪报隔离。
