# 子代理启用与任务分配

只在实际委派有明确收益时使用。主 agent 保留范围取舍、共享定义和整合判断；简单讨论、局部更新和普通自检直接完成。独立阅读按 [适用条件](document-structure.md#交付前的阅读检查) 启用，不是每次交付的必经步骤。

## 按收益与依赖启用

适合委派的问题包括有边界的材料勘察、输入已经明确且可以独立核对的设计切片，以及确有需要的独立阅读。父子 Issue 组织工作范围，不决定 agent 数量，也不按五阶段分配代理。

共享规则尚未收敛、频繁依赖同一中间状态或只能修改同一正文时，先顺序处理；必要输入就绪且写入能够隔离时再并行。分析委派不扩大为产品编码或外部系统操作。

## 最小任务输入与写入归属

提供问题、预期结果、范围与排除项、必要原始材料或入口、允许动作和返回要求。固定版本对并发或评审确有必要时标明修订，不为一次委派专门制作输入包。

同一工作区保持单写者，独立写入使用隔离位置；只读评审不改受审正文。子任务完成后主 agent 核对结果与有效需求，再整合到原主题，不直接将代理完成视为交付通过。

## 变化与交接

范围或共享输入变化时，通知受影响代理停止旧写入，核实已有差异后再调整分工。无关子任务可以继续，旧测试不自动证明新定义通过。

回传结论、必要证据、未解决问题和实际改动位置；交付说明或已有任务足以承载时，不再另存分配、回传和整合报告。
