# 设计输入与双向追溯

当需求交给架构、模型、研发测试或另一位协作者时读取。输入包是有效定义的索引与交接契约，可以是现有文档中的一节，不是要求另建一套模型或抄写一份需求。深度随用途调整，架构／模型探索不要求先完成全部用户故事。

## 确定本次输入

记录分析范围、目的、输入来源、适用约束、已确定的选择、仍有效的假设、期望设计深度及需要保存时的输出位置。有文档时记录实际位置与修订号；仅有对话或观察时记录可定位的来源，不补造版本或要求先生成前序文档。正式交接前按[就绪检查](readiness.md)判断；尚有关键缺口时可做方案探索，但不能交付为确定设计。

输入包先说明本次范围、目的与整体依赖，再索引唯一规范位置，不按聊天／确认先后排列输入。追溯信息与各类证据按 [内容归属与分区](document-structure.md) 管理，交接单独保存。

输入以当前有效需求定义为准，来源、变更历史、样例与验证证据分别关联，沿用 [内容与版本约定](document-structure.md#先判内容性质再判维护责任)。样例可以检验设计，但样例的领域对象、账号或字段不自动成为产品规范；只有已明确属于产品范围的概念才作为需求输入。草稿没有基线号时使用可定位的内容修订或保存快照，不让更新时间相同却内容不同的材料充当同一固定输入。

按相关性索引：

| 输入类别 | 交接的规范定义 |
|---|---|
| 目标、场景与故事 | 用户结果、角色与情境、价值、范围、优先级、正常与异常路径 |
| 信息与状态 | 关键概念、属性口径、关系、责任、生命周期与历史策略 |
| 操作与规则 | 输入输出、前后条件、规则定义和调用位置 |
| 协作与流程 | 影响矩阵、条件分支、交接责任、时效与失败恢复 |
| 查询与权限 | 数据粒度与计算口径、角色操作及数据范围 |
| 接口与质量 | 外部契约、兼容性、运行约束及验证条件 |
| 验收与未决 | AC 的条件／动作／结果、验证方法、必要数据环境、证据状态、阻塞关系和条件性假设 |

表中只放定义的引用及版本，不复制正文。下游不能在生成设计时无声重新拆分业务、添加审批、修改统计口径或选择失败后果。发现输入矛盾返回具体缺口；可以提出修订建议，待决定生效后更新相关定义。

另外按需索引验证对象、输入／环境、计划覆盖、实际结果和限制，标明各证据检验的需求或假设。产品范围不由样例覆盖反推，设计适用性也不能仅由一个样例通过证明；明确执行或技术约束不能以“只保留业务需求”为由删除。

## 可追溯关系

沿用项目已有追溯工具或表格；没有时按当前范围维护：

| 需求／场景／故事 ID | 规则／操作／契约引用 | 架构／模型／设计位置 | 验收 ID | 研发／测试任务 | 实现／测试证据 | 输入修订号 | 覆盖状态／缺口 |
|---|---|---|---|---|---|---|---|

关系允许一对多、多对一，不施加特定框架的一对一约束。不需要建模时，设计列可引用直接实现说明，或说明本轮不需要设计；有必要设计但未做时记为缺口，不能误记为不适用。

正向核对：当前正式需求是否都有承载位置与验收方式，遗漏项是否显式登记。反向核对：设计、界面操作、接口和任务是否都有需求或必要技术约束依据，是否引入未决定的业务能力。技术支撑项可以关联所支撑的用户结果与验证方式，不必编造用户需求。

映射表用于检验覆盖，不替代当前模型、架构或交付方案的说明。下游先形成适合本轮用途的完整结论，再关联规范与证据；具体接口绑定、模型实例和测试用例标明适用范围，不能从样例逐项复制出通用设计、故事或 AC。

研发测试交接以独立故事正文及必要引用为单位：明确本次目标和行为、可执行任务及产出、验证条件与预期、依赖和阻塞。设计引用定位到有效版本及具体章节，说明在本故事中使用的契约；追溯表不能替代这些内容。故事及任务的唯一正式位置遵循 [第四阶段保存规则](../stages/delivery.md#保存与任务落地)。

一个故事可关联多个研发和测试任务，一项设计或回归测试也可支撑多个故事。技术前置任务关联所支撑的用户结果或质量目标，不强制虚构故事。

进入实现阶段后补实际模块／接口、实现版本、测试用例和执行结果位置；分析阶段只填写已存在或明确标为拟定的落点，不伪造代码链接和任务编号。AC 已定义、测试已设计、测试已执行及结果通过分别记录，未执行处明确留缺口。

## 变更传播

变更生效后，从改变的定义沿上述关系追到场景、故事、协作链、架构、模型、验收、研发测试任务及既有执行结果。旧测试结果不自动证明新版本通过；将尚未复核的项标为“需复核”，保留原输入修订号，复核完成后再推进版本，不先把全部版本号改成最新。

引用关系不完整时，针对被改术语及旧值做有边界的搜索补充影响判断；没找到引用不等于没有影响。详细处理沿用[变更分析](../changes/impact.md)。
