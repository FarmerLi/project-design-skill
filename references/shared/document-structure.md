# 文档结构、内容归属与材料管理

用于保存或整理需求与设计。默认直接更新当前主题，让读者能够理解结论并继续工作；文档数量由实际阅读和维护需要决定。

## 从整体到局部

先说明对象、目标、范围和主要结论，再解释关键关系、场景与必要细节。主文保留整体认知，只有细节已经干扰主线、存在独立维护责任或不同读者需要时才拆专题。短而紧密相关的内容放在一篇，阶段也可以是章节。

## 先判内容性质，再判维护责任

需求说明期望行为，模型说明概念与状态，架构说明实现机制，交互说明用户怎样操作和获得反馈，任务说明本次工作与验收。来源、选择理由和验证结论可以在所属主题用简短注释或小节表达，保持当前结论容易找到。

聊天过程和完整工具日志通常无需保存。对解释取舍或复现结果确有必要的原始材料，通过引用关联；长日志和运行输出沿用实验或工具的已有位置。

## 主题边界与唯一维护位置

### 先确定分工，再创建或扩写文档

新内容先找已有主题，合并同义定义，保留独有条件和例外。完整规则只在一个位置维护；主文、组件与任务通过摘要和具体引用承接各自责任。确有跨组件共同契约且现有章节无法清楚承载时，再考虑独立专题。

### 区分定义、摘要与应用

同一规则可以在需求中定义，在架构中说明实现，在验收中表达可观察结果。各篇保留本方新增信息和必要上下文，引用权威章节；不因去重删掉组件责任或可判断的 AC，也不复制全部上游规格。

### 按语义检查交叉与重复

对照本次主题与直接相关内容，检查换措辞的重复、冲突和失效结论。冲突按有效依据处理，无法判定时标明具体差异；不按文件时间直接选一份，也不扩成全项目整顿。

## 正文使用对象语言

正文直接描述行为、机制及成立条件。必要来源可就近注明文档、链接或用户明确要求；事实、建议和待决取舍须可区分。仅在原话本身有研究或解释价值时保留访谈原文，无需把每次对话整理成独立来源记录。

## 正式文档与辅助材料分区

默认把结论、关键理由、未决问题及简短验证结果放在当前文档或已有任务的合适章节。项目已有正式／辅助分区时沿用其约定；两类信息可用章节区分，技能不要求为每类信息建立文件或目录。保存位置沿用户指定位置或现有结构确定，必要时查 [项目上下文](project-context.md#文档位置与组织约定)。

### 辅助材料何时值得独立保存

| 信息 | 默认承载 | 独立保存的条件 |
|---|---|---|
| 来源与关键取舍 | 原主题的依据注释、理由或引用 | 原始访谈／调研需保留，或重大取舍的备选、理由和影响需要长期解释 |
| 变更 | 直接更新正文，利用 Git／平台历史 | 跨多项成果的迁移、兼容或范围调整需要持续跟踪 |
| 交接 | 当前任务中的未完成项和下一步 | 中断或转交后，仅看正文无法恢复实际进展及阻塞 |
| 验证与评审 | 任务、回复或现有报告中的结果摘要 | 实际实验需要复现，或评审有实质意见、整改或项目留证要求 |
| 图源与附件 | 沿用现有附件／实验位置 | 正文需要独立图片或可编辑源 |

独立保存前先检查已有位置能否承载，并明确材料服务谁、何时会再用。对同一事项复用一个记录或任务，避免分别再建来源、决策、变更、交接和评审报告。关键决定可在该记录的一处完整说明，其他位置只引用。已有跨记录 ID 继续保留，只有需要稳定引用时才新增编号。

实际代码、实验及原始输出继续在所属工程或实验位置维护，设计只引用结论与必要证据。单次自检无问题时在交付说明中简述即可；不为证明检查过而另建检查清单、快照清单、哈希文件或报告。并发评审或正式冻结确需固定输入时才使用修订或快照。

## 更新与清理

1. 将有效变化整合到原主题，处理本次范围内的旧结论、重复和已解决问题，同步必要图文及引用。
2. 保存后回读正文和受影响链接，核对关键语义、边界和验收。配置与索引仅在入口或组织方式变化时更新。
3. 本次新建的临时草稿整合后可清理。既有辅助材料不会因新规则自动删除、搬迁或批量归档；仅在用户要求整理或维护范围明确包含它们时处理。

整理大量既有材料时，先依据用途、引用、恢复与复现价值判断保留、合并或清理：有效正文并回原主题，仍有用的记录原位复用，有必要保留的历史沿版本历史或既有归档查找。用途不明、仍被引用的证据先保留核实；迁移同步当前入口，保留独有约束和既有 ID。不为少文件把所有记录塞成另一份不断增长的总日志，也不为保留所有过程而再复制一套归档。

## 图示辅助理解

关系、协作或变化难以用短文说明时用图。模型和架构设计通常需要范围总览；代表性场景解释关键关系与约束，简单图可以就近带读。图文使用相同术语，重要方向、状态、基数或边界要清楚。

### Mermaid 与 SVG 的选择

优先遵循项目要求。流程、状态、时序和模型关系通常用 Mermaid；整体架构也可使用 Mermaid，复杂分层或布局需要时用 SVG。按可读性选择，避免为图种另造一套附件。

每图只维护一个权威源，需要跨平台展示时再导出副本。检查图文一致；实际预览后才报告视觉检查，只有图源时如实说明。图或格式问题不扩大业务范围。

## 交付前的阅读检查

默认由编写者回读当前正文及必要引用：能否理解本轮目标、结论、关键行为与限制，是否遗漏重要约束或存在冲突，后续用途所需信息是否充分。无需逐项报告通用清单。

用户或项目明确要求独立评审时执行；复杂跨主题交接、重大模型／接口变更等需要额外把关时可安排。其他局部交付以自检完成，不因未安排子 Agent 而标记未完成。

独立评审使用未参与编写、不继承主会话历史的上下文，提供用途、范围、当前正文和必要规范引用，不提供作者自评或预期答案。评审者返回理解、实质缺口及位置，主 Agent 处理影响本轮用途的问题；关键修改后按需复评。用提交、平台修订或确有必要的快照固定输入，不默认制作指纹包。

结果简述在交付说明或已有任务／记录中；有实质整改或留证要求才另存报告。实际要求的独立评审无法完成时如实说明原因和影响，不冒称通过。阅读检查仅证明所读范围的可理解性与一致性，不代替运行验证。
