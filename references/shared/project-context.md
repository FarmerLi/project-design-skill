# 项目上下文与技能交接

项目上下文用于长期恢复入口分散、跨技能协作或用户要求共享定位信息的场景。已有配置直接使用；当前任务和文档入口已清楚时，无需为保存或持续讨论专门建配置。

## 定位与建立

先从用户指定位置、当前任务、README 或已有索引定位材料。存在 `.project-context.json`、`项目上下文.md`、`PROJECT_CONTEXT.md` 或远端等价章节时复用；不建立竞争来源，也不因技能更新转换格式或搬迁文档。

确需共享配置且没有现有载体时，可使用项目根 `.project-context.json`，按 [模板](../../assets/project-context-template.json) 仅填写当前必要入口。项目规则已有明确配置要求时遵循。

## 最小共享字段

与 `coder-assistant` 的已有字段兼容；全部按需要使用，未知或未用字段可省略。

| 字段 | 含义 |
|---|---|
| `project.name`、`project.repository`、`project.path_base` | 项目身份与本地路径基准；配置在项目根时基准为 `.` |
| `documents.formal_root` | 当前需求和设计入口，本地路径或远端 URL／ID |
| `documents.support_root` | 已有辅助材料入口；没有独立辅助区可省略 |
| `documents.organization` | 必要的现有组织约定，简述或引用规范；缺少此键不影响现有配置使用 |
| `tasks.entry`、`tasks.mapping` | 任务入口与已有映射；关系可直接在任务中表达，无需单独映射表 |
| `handoff.design`、`handoff.development` | 确有交接时的入口，可指向同一文件／任务或不同章节 |

保留已有扩展字段。JSON 配置保存后解析回读；相对路径以 `project.path_base` 为基准，其自身相对配置文件解析，会话 worktree 按对应项目根定位。配置不存业务正文、执行历史、凭据或授权开关。

## 文档位置与组织约定

用户指定位置和项目已有组织规则优先；配置提供导航。缺少字段时直接从现有目录、页面或索引确定本次位置，不先补齐配置。只有新增共享入口或组织约定确需长期使用时，才更新相关字段。

新项目保存一份文档时选择与请求一致的最小位置即可；项目命名未约定时使用中文文件名，保留扩展名。无需先设计正式／辅助目录树，也不预建阶段、来源、交接或验证目录。内容的分工见 [文档组织](document-structure.md)，分工可以通过章节实现。

### 没有本地项目目录时

直接使用已授权页面或任务，已有入口清楚就沿其引用继续。确需共享导航时在现有页面保留必要入口；无需建立本地仓库或正文镜像。

## 与 coder-assistant 交接

当前任务及必要需求／设计引用足够说明目标、行为、验收、依赖和阻塞时，可以直接交接。跨技能使用相同配置只是定位方式，不要求两个技能同时安装，也不自动增加记录。

确有恢复缺口时按 [工作约定](working-contract.md#每轮恢复与保存) 更新一处交接。开发补实际实现与验证证据，设计侧依据其影响修订原主题；不复制整套正文或因技能切换重建任务。已有配置中的双向字段继续保留。

## 按需执行与更新

文档保存按 [文档维护](../integrations/document-maintenance.md) 执行；任务写入按 [任务落地](../integrations/task-tracking.md) 执行。入口变化才更新配置和相关引用；地址不代表写入授权，已有明确授权沿用。
