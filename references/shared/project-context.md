# 项目交付配置

用 PROJECT_CONTEXT.md 记录“任务建到哪里、文档维护在哪里、如何关联与更新”。它是任务和文档操作的配置，不仅是参考资料地址索引。

## 定位与建立

统一放在被分析项目根目录：`<项目根目录>/PROJECT_CONTEXT.md`，不放在技能包或 docs/project-analysis 下。项目根目录不明时先明确目标项目，不把当前技能开发目录当作业务项目。

首次持续分析或需要落地任务／文档时，若文件不存在，使用 [模板](../../assets/project-context.template.md) 在该根目录建立，按已知资料填入，未知项按当前动作需要补充。已有配置中的相关信息可引用或迁入，不要求重复提供。多项目工作区在各项目根目录分别配置；路径均相对于配置所在的项目根目录。临时咨询不要求创建文件。

配置包含两组独立目标：

- **任务管理**：Jira 等系统的实例、项目、实际任务层级、父项、字段约定、执行时机与任务关联记录位置。
- **需求文档**：本地目录或 Notion／Confluence 的正式目标、文档组织方式、已有页面、更新范围、草稿和正式版本关系。

选择某个目标后只保留有关配置，不要求用户同时填写所有平台。不在配置中重复需求正文、进度和业务决策，也不保存凭据。

## 使用配置

- 用户要求拆解后创建或同步任务，读取 [任务落地](../integrations/task-tracking.md)。先准备具体拆分，再按配置创建／更新；恢复开发时复用已关联任务。
- 需要保存或更新需求文档，读取 [文档维护](../integrations/document-maintenance.md)，按选定正式位置维护已有内容。各阶段默认文件名只是未配置时的本地约定，不强制再创建本地正式副本。
- 已有明确的持续写回授权按约定执行，不每轮重复确认。仅记录系统地址不代表已要求写入。执行前先完成可审阅内容；若必须澄清，只询问阻塞目标定位、字段映射或授权范围的缺口。
- 需要访问某平台时，按当前环境实际可用的连接器、CLI 或相应技能执行，不假定有链接就能访问。配置也不授权额外评论、通知或消息发送。

缺少目标或权限时继续完成独立的分析和草稿，说明哪些尚未落地；不能把本地完成写成 Jira 已创建或远端文档已更新。

## 更新与来源

任务状态和需求正文可以分别以不同系统为准，不把二者当成重复副本。来源冲突时按已约定范围和版本核对；无依据则保留差异并澄清。

配置变更后更新受影响的交接和关联链接。切换平台或目标不是自动迁移授权，不自动复制历史文档、删除旧任务或重建全部内容。

配置按约定变化更新，结果状态和交接遵循 [工作约定](working-contract.md)。
