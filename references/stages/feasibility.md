# 价值与可行性评估

本文件是第一阶段“需求探索与澄清”的按需子方法，也可单独评估价值或成立条件。技术架构与 demo 执行交给 [第三阶段](architecture.md)，可按关键风险提前调用，不作为另一个必经主阶段。

## 方法目标与输入

基于当前目标、场景和约束，判断问题是否值得投入、候选路径在什么条件下可行，并形成有证据支持的推进、缩小范围、先验证或暂缓建议。本方法支持投入与后续分析决策，不确定完整功能范围，不以评估完成代替可行性验证或交付承诺。

最低输入为目标、用户／场景、已知约束；来自对话也可，不要求补齐其他分析文件。读取 [交接契约](../shared/working-contract.md)，复用本轮有关材料及有效决定。输入缺口不阻止开始分析，但影响结论的部分保持条件性。

## 工作方法

先用已有信息形成判断草稿，按以下依赖补足依据；已有答案直接复用，不将步骤变成逐项问卷。

1. **明确评估对象。** 说明本轮支持什么决定：项目是否启动、增量能力是否值得投入，或既定方案在指定约束下是否成立。复用目标、成功信号、范围和硬约束，区分已定决定与可选择部分；发现关键冲突时指出影响及待决取舍，不补跑完整目标澄清。
2. **评估价值。** 检查问题规模与频率、当前做法及不改变的后果、受益者和预期改善，关联可观察结果与证据强弱。区分已知事实、收益估算和待验证价值假设。
3. **比较相关选项。** 按相同目标与可比范围，比较收益、主要投入与成本驱动因素、硬约束满足情况及风险；范围不同须说明差异。按实际意义纳入维持现状、流程改进、复用／采购或较小范围开发，不强制凑齐选项或评分。已有方案明确时可只评估其成立条件与必要调整，说明无需重新比较的原因。
4. **检查可行性与关键假设。** 只检查可能改变当前建议的技术与数据、人员和时间、外部依赖、使用与推广条件；合规或采购约束仅在相关时展开。找出最可能推翻价值判断或方案的少数假设，区分决定项目是否成立的前提与可在明确边界内承担的剩余风险。
5. **组织验证与修订判断。** 优先复用已有证据，定义关键验证任务；业务事实从材料或相关人员获得依据，技术问题通过查证或已获授权的试验补证。实际取得新证据后，回到受影响的价值、选项和可行性判断，说明建议是否改变及原因；尚未执行则保留条件，不预写验证结果。
6. **收敛建议与后续边界。** 给出推进／缩小范围／先验证／暂缓建议、适用范围及成立条件，明确哪些是分析建议、哪些已由用户决定。按下方标准分别报告评估完成情况、概要就绪范围和实际验证状态。

## 分析约束

- **估算必须有依据。** 仅在数据、类比或计算假设可说明时给出收益／成本区间，并标明来源、口径与不确定性；明确标注区间不能替代依据。无依据时给定性判断及补证方式，不编造 ROI。情景假设数值仅用于探索敏感性，不作为实际收益预测或已证实的推进依据；没有资源数据不承诺排期。
- **保持已定约束。** 不无故重开明确决定，不为让方案显得可行而静默放宽目标或硬约束。新证据显示冲突时，列出冲突、影响和取舍事项；有授权的选择沿用授权，无须重复确认。
- **验证计划与执行分开。** 定义验证任务不等于执行试验。分析请求本身不授权原型开发、采购或生产操作；执行依实际授权，已有授权不反复确认。试验应明确对象、环境、资源边界和停止条件，超出边界时停止该试验，交付已有证据与缺口。
- **证据限定结论。** 验证结果只覆盖实际对象、环境和范围；“可做原型”、验证计划或文档完成均不代表已验证可行。来源与确认状态沿用公共契约，不将 AI 推测或用户沉默视为确认。

不默认调用适配器。用户已指定技术方案，或明确授权评估某方案时，按 [适配器目录](../adapters/catalog.md) 读取对应适配说明，只处理影响当前结论的风险，不展开完整设计。

## 最小产物

交付以下内容；需要保存时按项目配置维护，未配置正式位置时写入 `01-需求探索与澄清.md` 的价值评估章节；已有 `02-feasibility.md` 可以沿用：

1. 评估对象、所支持的决定、目标与范围、已定约束及来源；
2. 价值判断及证据强弱，相关选项的收益、主要投入、约束和风险比较；无需比较时说明原因；
3. 推荐结论、理由、适用范围、成立条件及改变建议的触发条件；仅在建议需要时给出首期可验证的范围假设，不将其当作最终范围或交付承诺；
4. 关键风险与验证任务：待验证命题、方法、通过／否决信号、所需输入、当前证据及结果状态；说明通过、失败或证据不足分别如何影响建议，最迟在哪个决策节点前解决，以及阻塞哪些后续工作。已有负责人或时间安排直接引用，无依据不虚构；无关键待验证项时说明依据，不生成空任务；
5. 评估完成情况、可交接范围与阻塞项，验证计划与已执行结果分列。

## 完成标准与交接

以能否支持本轮决定为准，按以下六项给出依据与结论；不以候选方案数量、文件数量或所有风险清零衡量完成。

| 检查项 | 本项分析达到什么程度即可 |
|---|---|
| 评估对象 | 本轮支持的决定、目标、适用范围及已定约束明确，无影响当前判断的对象歧义 |
| 价值依据 | 预期改善及依据可说明，事实、估算与假设分开；缺少量化数据本身不构成阻塞，但不能支撑的收益结论不得视为事实 |
| 选项取舍 | 相关选项已按可比口径比较，推荐理由可追溯；无需比较时说明原因 |
| 可行性条件 | 影响建议的约束、依赖和关键风险已识别，证据或缺口明确；项目成立前提与可承担的剩余风险可区分 |
| 推荐结论 | 建议与证据一致，明确适用范围、成立条件及改变建议的触发条件；证据不足以支持推进时，可形成有依据的先验证或暂缓建议 |
| 剩余未知 | 已说明影响、验证或解决方式、解决节点与阻塞范围，未将待验证项隐含写成成立条件已满足 |

上述标准用于第一阶段内部的价值与范围收敛，与公共 [就绪检查](../shared/readiness.md) 配合使用，分别报告：

- **评估是否完成：** 六项满足时，本轮评估可以完成；有依据的先验证或暂缓也是完整结果。若缺口使本轮建议本身无法成立，交付条件性草稿并标明未完成部分，不能仅凭列出风险宣称评估完成。
- **是否可供概要使用：** 对建议推进的范围，决定项目是否成立的前提须有支持证据，相关硬约束冲突已解决；剩余风险已验证，或其承担边界与必要验证安排已由有权决策者接受。记录接受依据、适用范围与解决节点，已有明确决定直接复用。仅对满足条件的范围标为“可供下阶段使用”。
- **成立前提尚未验证：** 先验证相关前提，不能以“接受风险并安排验证”替代支持证据。可并行分析无依赖部分，但受影响结论保持条件性；先验证、暂缓或仅完成文档均不自动获得概要就绪状态。
- **可行性验证状态：** 说明哪些命题已验证、未验证或未通过，以及证据适用条件，不用评估完成或风险接受替代实际验证。

独立运行时交付当前结果即可结束；本轮结束不等于评估完成或概要就绪，概要就绪也不自动授权其他工作。已授权连续分析时仅继续可推进部分；暂缓不为凑全流程继续详细设计。需要持续维护或交接时按配置更新概览、相关决策和交接，临时咨询在回复中说明即可。
