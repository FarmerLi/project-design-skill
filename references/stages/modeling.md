# 领域与数据模型探索设计

## 阶段目标与输入

依据需求或已有实现，形成本轮范围内可独立理解的领域与数据模型，说明概念为何存在、彼此如何关联、如何承载行为与约束，并提出有依据的优化、重构及演进方案。“全视图”指相关视角和边界完整，不要求扫描整个项目或为所有项目建立数据库模型；图表、字段和映射齐全不等于模型语义已完整。

最低输入为相关场景、规则或实现材料及分析范围，可附已有架构。读取 [工作契约](../shared/working-contract.md)、[设计输入](../shared/design-input.md) 和 [通用分析规格](../shared/analysis-spec.md) 的相关维度。完整分析默认先形成概念与逻辑模型，用业务语义、边界、规则及数据关系驱动架构探索，再结合架构完善物理设计；也可与架构并行或往返，不等待全项目架构冻结。

## 工作方法

1. **界定模型范围。** 明确是解释现状、设计新增能力，还是优化／重构，并区分产品自身、实际集成对象与验证样例。已有项目只沿相关模型定义、迁移记录、读写入口或契约取证；分别记录观察到的结构、业务语义推断及尚未核实的运行行为。
2. **选择必要表达。** 先用领域术语表达含义，再决定表、关系图、状态图或正式模型格式。需要比较方法时读 [建模选择](../selection/modeling.md)，已有方法直接复用其有效规范与表达；不增加显式模型也可成立，不默认本体规范。
3. **建立视图。** 依据下表展开相关部分，包含模型设计时按 [模型图输出](#模型图输出) 交付总览图并结合场景带读，共享规则保持唯一规范定义。架构尚未定时可以先完成概念与逻辑设计，将物理设计保留条件。
4. **检验模型。** 用代表性场景走过读取、创建、变化、失效及必要的异常／反向路径；核对关系、状态、规则、权限和统计口径的一致性。有解析器或样例验证时记录实际结果，图表齐全不代替验证。
5. **形成演进方案。** 对已证实的问题说明优化目标、改动范围和取舍；已有项目区分现状、目标、差异和演进路径。关系或一致性要求需要架构承载或调整时交给 [架构验证](architecture.md)，业务规则不明时交回需求澄清或故事细化。

需要按指定 schema 或元规范输出结构化模型时，先读取实际规范与版本，核对表达范围及格式。依据不足时只形成概念或映射草案，不猜测字段、不声称已兼容；格式校验与语义检查分别记录。该要求不决定技术底座或扩大分析范围。

## 模型正文与专题组织

- **提炼语义。** 将对话、schema 和代码结构还原为概念含义、职责、身份、关系及规则，再选择表达。概念或字段说明应能回答它服务哪个场景、由谁维护、怎样约束行为；不以“用户要求增加字段”或源表原样抄录代替定义，也不从实现默认值推定业务政策。
- **辨明归属。** 平台自身的模型、被接入领域的模型与某个样例的实例／字段映射按实际责任区分。通用设计说明如何表达或承载不同领域，具体绑定标明适用系统、契约与版本；样例中的实体、角色和字段不自动成为平台固定 schema。设计对象本就属于该领域，或某外部契约已明确纳入集成范围时，保留其正式概念与约束，不为抽象而移走必要语义，也不强制建立三层模型。
- **归并定义。** 将新增信息合入已有概念、关系、状态或映射，消解同义重复与同名异义。语义发生变化时检查相关视图、规则、读写和迁移影响；等价改名同步相关图表及引用，不新建一套并行模型或机械发布新版本。
- **推演并回读。** 用本轮代表性场景说明模型如何表达输入、变化和结果，检查关键规则有落点、每个设计元素有需求或技术依据。去掉聊天、旧方案与验证数据后，读者仍应能解释模型边界及关键语义；样例用于展示和检验，不能承担通用定义。

来源、确认状态和替代关系按 [内容与版本约定](../shared/document-structure.md#先判内容性质再判维护责任)维护。样例核对、机器校验与迁移试验的过程和结果单独关联，当前模型只保留影响其适用性的证据结论及限制。

## 模型全视图

按当前用途逐项标明已覆盖、需补充或不适用及理由，不把未知写成不适用。

| 视角 | 关注内容 |
|---|---|
| 领域语义 | 核心概念、业务含义、标识、关系基数、可选性、维护责任及上下文边界 |
| 行为与生命周期 | 操作、状态、允许与禁止的变化、规则、关键事件及失败／反向影响；无状态对象不强造生命周期 |
| 逻辑数据 | 属性口径、类型、唯一性、引用、历史策略、权威来源与派生数据，查询和计算粒度 |
| 物理承载与流转 | 已有或拟定存储、接口结构、读写路径、跨系统流转及一致性；索引和冗余须有访问需求与质量依据 |
| 演进与兼容 | 现状和目标的差异、依赖影响、迁移与切换方式、数据校验及恢复条件 |

无状态工具或 SDK 可以只交付输入输出、类型、错误与兼容契约；说明持久化及迁移不适用，不为满足阶段形式引入对象体系。字段完整程度取决于本轮设计用途，不能用概念图冒充已完成物理设计。

## 模型图输出

本轮包含领域或数据模型设计时，至少交付一张覆盖该范围的模型总览图，与语义说明一起输出。领域概念关系图或逻辑 ER 图均可，按模型层次选择；已有图足以解释范围时直接复用。字段清单、schema 和映射表用于补充图。仅做字段释义、无状态函数契约核对或建模方法比较时，按理解需要选用局部图，不强制总览图，也不为出图引入持久化或额外对象。

| 要理解的问题 | 适用图示与表达重点 |
|---|---|
| 核心概念是什么、如何关联 | 概念关系图：业务含义、上下文边界、维护责任与关系；基数、可选性在影响规则时标明，未知不猜填 |
| 数据如何组织、相互引用 | 逻辑 ER 图：标识、主要引用、基数与关键约束；不需要数据库时保留概念／类型关系，不画成已定物理表 |
| 对象如何变化、规则约束什么 | 状态图或活动图：合法转换、触发条件及关键失败／反向路径；无状态对象不强造生命周期 |
| 现状如何演进到目标 | 现状／目标对照或迁移流程图：复用、调整、旧新映射及切换依赖；只在本轮涉及演进时补充 |

总览未能解释关键生命周期、关系或演进时，补充对应局部图，不强制绘制全部类型。现状与目标、平台定义与样例映射按实际边界标明，差异过大时分图展示；读者应能辨认规范定义、候选设计与验证样例。

格式遵循 [Mermaid 与 SVG 的选择](../shared/document-structure.md#mermaid-与-svg-的选择)，以清晰理解业务概念、关系和规则为目标；模型关系总览仍按关系图处理，复杂图可采用 SVG。展示、保存和可读性检查遵循共用规范。沿代表性场景带读对象怎样建立关系、状态怎样变化及规则如何约束；无状态模型可说明类型之间的输入输出关系。语义或结构修订时同步图、场景说明及相关引用。

## 优化、重构与迁移

每个建议关联可观察问题或需求，例如语义混淆、历史丢失、读写瓶颈或数据不一致；没有证据时标为候选，不为结构美观扩大范围。

涉及已有数据或调用方时，按相关性说明：旧到新结构映射、历史数据处理、约束校验、接口兼容、切换依赖、失败后的恢复策略与验证方法。不可逆操作标明限制和所需决定，不能默认可回滚。只交付设计不等于执行数据迁移。

关键删除、归档、历史保留、金额口径或失败后果需要有效业务依据，不能从当前表结构、外键默认值或行业习惯反推为已确认政策。

## 最小产物与完成标准

按本轮用途交付：范围与输入来源、适用视图及覆盖状态、需求／场景到模型的映射、检查证据与缺口。包含模型设计时交付模型总览图、场景带读及必要的局部图；优化或重构任务另交付现状／目标对照、改进理由和演进方案，无变更请求时不强制提出重构。

正文先给范围、概念与上下文全景和代表性关系图，再沿关键场景解释语义、规则承载及数据关系，最后按需要深入物理与演进设计。复杂领域、独立生命周期或迁移可拆成专题，专题先说明在整体模型中的位置，再解释局部关系和约束；过深时继续分子专题。字段、schema 和映射表放在所属对象下，不让主文变成字段仓库或链接索引。具体遵循 [从整体到局部](../shared/document-structure.md#从整体到局部)。

按项目上下文的入口与组织约定保存，在既有模型主文或专题中维护，细节引用模型的唯一维护位置，不预设阶段文件名或专题子目录。来源、样例校验及迁移运行记录放辅助分区，独立图源和导出文件放附件区；整合完的临时模型片段按 [材料清理规则](../shared/document-structure.md#更新与清理) 处理。

按 [就绪检查](../shared/readiness.md) 判断：关键语义与关系明确；相关操作和规则能被表达；视图之间以及与架构之间无未解释冲突；必要演进方案可检验。业务规则未决或迁移约束不足时只交付条件性设计，区分模型设计完成、人工核对、机器校验及真实迁移验证。

交接前按 [独立阅读评审](../shared/document-structure.md#交付前的阅读检查) 由独立上下文子 Agent 读取当前正文及必要规范引用，检查无需比较修订历史或解读某份样例，就能说明关键概念为何存在、如何协作、约束在哪里及仍缺什么。包含模型设计时，所需总览图和场景带读已交付，关键关系及边界可辨，图文一致；保存及预览状态如实记录。已解决问题退出当前清单；未复核的关联设计和证据保留原输入版本，不用统一改号表示已适配。

向 [架构探索与验证](architecture.md) 提供当前切片的概念与逻辑模型、业务边界、规则及一致性要求；依赖技术选择的物理设计保留条件，结合架构结果补充。向 [原型与交互设计](prototype-interaction.md) 提供对象状态、关系、权限后的可见范围和操作可表达性，向 [需求细化与交付推进](delivery.md) 提供当前切片的设计与缺口；细化发现新规则时同步复核相关模型，不把模型定稿当成禁止需求反馈的理由。
