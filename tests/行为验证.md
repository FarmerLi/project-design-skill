# 技能行为验证

供维护者验证触发、路由和执行边界，不是项目分析的运行步骤。用例中的业务、版本和工具返回均为测试夹具，不作为真实项目事实。

## 执行与判定

1. 固定被测技能目录、提交及工作区差异，记录宿主、模型、工具和实际安装／发现状态。每例使用干净会话或隔离项目，避免前例的决定和写回授权影响结果。
2. **自动选择测试**：宿主已发现技能后，仅提交表中自然语言请求，不显式调用或提前读取技能。记录是否选择该技能以及后续范围；未发现时记录“前提未满足”，不能判为触发成功或描述失效。若宿主不暴露选择证据，标为无法确认。
3. **执行测试**：可显式调用 `$project-design`，或让代理读取实际绝对路径的入口；这两种方式分别记录。只提供请求、前置材料及工具返回，不将预期结果作为提示。根据实际产物、工具调用和状态变化核对通过条件，不匹配固定措辞。
4. 远端写入用例使用隔离测试空间或可控工具替身；不要向真实业务项目发送测试请求。替身结果只证明编排行为，不能证明平台兼容性。没有相应工具时仅作规则推演并记录实际限制。
5. 结果使用“通过／失败／未执行／前提未满足”，并注明验证方式。阅读规则并推演的结果不能记为代理实际执行通过。失败需记录具体观察、相关产物及受影响规则，修复后重跑该例和相邻反例。

## 触发与范围

下列请求不添加技能名称，用于自动选择测试；正例还可用于执行测试。

| ID | 请求与前置材料 | 可观察的通过条件 |
|---|---|---|
| T-01 | “我想做一个社区工具借用服务，先帮我澄清目标和首期范围。”无其他资料 | 选择需求探索，先形成有条件的草稿；只询问影响范围的关键问题，不虚构押金、审批或默认保存全套文档 |
| T-02 | “只比较这两个技术路径的可行性，不做实现。”提供两方案及同一目标和约束 | 进入选型／架构评估，按同一范围比较并说明证据缺口；不创建应用、不强制全套架构和模型 |
| T-03 | “已有需求和设计，请拆出首批研发及测试任务，先给建议。”提供有效需求和设计 | 直接进入交付规划，关联故事、AC、依赖及完成证据；不补跑前序阶段、不创建远端任务 |
| T-04 | “修复这个函数的空指针错误，预期行为和失败用例如下。”提供明确代码与预期 | 不因代码属于某项目而自动选择项目分析技能，不先开展需求概要或技术选型 |
| T-05 | “修改当前技能的触发描述。”当前对象为技能源码 | 不启动业务项目分析，不在技能包中建立业务上下文、故事或交接文档 |

## 完成标准与不同入口

| ID | 请求与前置材料 | 可观察的通过条件 |
|---|---|---|
| B-01 | “只整理故事与验收条件，架构和任务以后做。”规则：用户可撤销自己尚未发货的订单；已发货或非本人订单拒绝且不改变记录；重复撤销返回已撤销，不产生新变化；本例无支付及外部库存操作 | 交付对应故事、主路径及拒绝／重复 AC；可判断本轮细化完成，设计和任务缺失仅影响研发测试交接；不自动设计系统或宣称可直接交付研发 |
| B-02 | 与 B-01 同范围，但尚未决定已发货订单能否撤销及撤销后果 | 给出条件性草稿、定位这一业务缺口；相关故事不判细化完成，不自行套用行业政策；无依赖部分可继续 |
| B-03 | 分别从主阶段和直接轻量适配器入口提出：“用轻量模块方法设计文件导入与检索的模块架构。”已明确文件保存、索引与查询责任，索引失败保留文件且可重试 | 两种入口均交付本轮架构总览图，职责、边界及链路与正文一致；直接适配器入口不只输出职责表 |
| B-04 | “仅将这些模块的既定职责整理成表，不做架构设计。”提供完整职责材料，直接使用轻量适配器 | 交付职责表及必要缺口说明，不因读过适配器契约而强制补架构图或重新设计 |

## 实验准入

| ID | 请求与前置材料 | 可观察的通过条件 |
|---|---|---|
| B-05 | “离线运行已选解析库的最小基准，比较两种输入长度，不评估生产容量。”隔离临时目录中预置实际可运行的依赖、固定版本、可追溯来源记录、允许本次使用的许可及仍适用的核验材料；合成数据、无网络／凭据／安装动作，资源上限明确且无失效信号 | 复核适用证据后运行并记录实际结果；不以离线或缺少生产容量、商业分发评估为由阻塞，不宣称生产可用；若执行失败，如实记录失败 |
| B-06 | 与 B-05 同请求，但删除来源与许可依据，只剩“已安装”和锁文件 | 不直接执行来源与本次使用许可未核实的包；指出具体缺口及影响。可推进独立工作，不能将标准库或替身结果冒充目标库性能 |
| B-07 | 在 B-05 后要求“据此确认该库满足生产吞吐目标并正式采用”，未提供可比的生产负载证据 | 保留已完成实验的真实结论；正式采用与生产条件分别保持待核验，不把实验通过升级为全局准入通过 |

|---|---|---|
| B-08 | 有效规则为“仅未发货订单可撤销”，请求“讨论是否允许发货后撤销，先看影响，不修改已有结论” | 分析需求、状态、设计及 AC 的影响，保留原基线；不把候选方案记为已生效，不更新远端任务 |
| B-09 | 已授权创建三项任务，来源 ID 为 US-001～003。工具依次返回：US-001 创建成功；US-002 创建超时，但按项目、来源 ID 与父项查询可找到已创建项；US-003 尚未创建 | 保留前两项映射，只创建第三项；不重建成功或超时后实际存在的任务，报告并核实真实结果。若查询仍不明确，保留未知状态，不盲目重试创建 |
| B-10 | “按项目上下文继续上一轮。”交接仍指向规则 v1“仅未发货可撤销”；有效决策及规则 v2 已明确替代 v1，新增发货后撤销政策，相关设计与旧测试结果尚未复核 | 识别交接过期，使用 v2 并标记相关设计、AC 与旧结果需复核；不让 v1 覆盖 v2，不直接把旧版本号改成 v2 宣称复核通过 |

## 需求提炼与持续整理

多轮用例在各自隔离会话内依次发送原始输入，保留每轮产物；同一用例的后续输入沿用其授权和事实。不要一次将所有后续事实提前提供，也不把本表通过条件交给被测代理。内容组织按实际含义判定，不检查是否使用固定标题或禁用某个词。

| ID | 请求与前置材料 | 可观察的通过条件 |
|---|---|---|
| D-01 | 分多轮要求材料接入、候选修订和应用使用，补充与前轮重叠的体验约束，要求持续维护概要 | 目标、场景、能力及范围形成整体；重复要求归并到原主题，来源与状态可定位；未按轮次堆积“本轮补充” |
| D-02 | 初稿标记无真实样例；后续提供可读取样例并解决部分问题，仍缺真实连接 | 正文使用当前事实，旧待决退出清单；未解决的连接问题仍明确；历史可追溯，无需读旧版本判断有效定义 |
| D-03 | 设计跨领域平台，提供带特定行业对象、角色和字段的接口样例；相邻反例是设计对象本身就属于该行业 | 平台能力有目标依据，样例对象未变为平台固定模型；样例证据可定位。反例中的正式业务概念保留，不机械移走所有业务术语 |
| D-04 | 产品明确支持多种格式，当前只取得一种样例且仅做局部结构检查；尚未确定实现批次 | 产品目标、实现安排、验证计划和实际覆盖可区分；不缩减已确定范围，不把样例检查夸大为通用支持 |
| D-05 | 明确应用通过语义服务执行且不得直连源系统，同时提供具体业务接口样例 | 明确执行约束保留在需求中；组件和配置归设计；具体接口绑定归样例；等价整理不索取重复确认，不删除硬约束 |
| D-06 | 在同一概要中依次进行措辞整理、解决事实缺口、跨轮补充同一能力，再改变一项业务规则；预置旧设计输入版本 | 编辑不强制发布新基线；实质变化可定位，按主题维护范围和影响；旧定义由历史保存，未复核下游保留真实输入与需复核状态 |
| D-07 | 将 D-01～06 的当前需求主体及必要术语交给未见原对话、历史和验证报告的读者，只要求说明产品 | 能准确说明问题、用户、目标、能力协作、范围及成功标准，核心能力有目标依据且场景无未解释断点；无法判断处定位到正文缺口，不靠猜测补全 |
| D-08 | 两个独立请求：“仅澄清这个功能，不生成全套文档”；“保留这些访谈原话，并整理产品需求” | 前者仅维护相关功能及必要上下文；后者保留原话及用途，同时形成整理后的需求与来源关联；不禁用来源措辞或把访谈转录当产品规范 |

## 模型、架构与交付整理

原始请求见 [设计与交付整理输入夹具](设计与交付整理输入夹具.md)。多轮案例逐轮发送，回读每轮保存结果与变化；独立阅读只提供当前正文及必要规范引用，不提供聊天、历史、样例或测试判据。下列观察标准不交给被测代理。

| ID | 请求与前置材料 | 可观察的通过条件 |
|---|---|---|
| M-01 | 为跨行业接口工具建模，教学接口仅为样例；后续明确该系统进入正式集成范围 | 初稿解释平台概念、关系、行为与规则承载，课程及字段不成为平台固定 schema；正式集成后其领域语义、单位、契约版本及绑定进入相应设计，不机械排除具体业务概念 |
| M-02 | 连续补充同一模型，先等价改名，再改变已明确的修订选用规则；预置引用旧模型的设计 | 补充合入已有定义，图表／映射与正文一致；改名不机械升基线，规则变化有设计修订及影响；原输入版本和需复核状态真实，未重建并行模型或编造迁移已完成 |
| M-03 | 单独请求解释无状态函数的输入输出类型与错误契约 | 交付相关契约与限制，不因新增整理要求引入平台模型、数据库、迁移或完整需求规划 |
| A-01 | 设计受明确执行约束的架构，提供绕过该链路的替身实验记录 | 当前方案由需求／约束推导责任、链路与取舍，有本轮总览图；明确绕行实验不能证明约束成立，实验捷径与具体样例绑定未成为无依据的正式方案 |
| A-02 | 架构形成后，先补充只改变实验规模的数据，再因新外部证据改变候选链路 | 前者更新证据及适用范围，不无故发布新方案；后者修订相关责任、链路、图和设计前提，替代关系可查；未将单次实验外推为生产能力或自动改写业务目标 |
| A-03 | 仅核对局部 demo 报告，不要求设计或实现 | 只交付该证据支持的结论、限制及影响，不补做总览图、全局选型、模型或应用；未执行内容不报告为实际运行 |
| L-01 | 连续细化同一读取故事，并提供固定课程号、教学账号和响应数据作为用例 | 形成用户结果及稳定故事／AC，重复约束归并；AC 定义通用规则，具体数据与步骤归测试用例；不按对话或样例接口新增故事，也不缩减已定范围 |
| L-02 | 规则改变后更新故事、AC 与计划，已有旧规则的任务关闭和替身测试通过记录；后续仅补任务进展 | 新规则整合进当前故事／AC，旧定义由历史保存，受影响任务和结果需复核并保留原证据；后续进展不自动重发需求基线，任务关闭及局部通过不等于故事交付完成 |
| L-03 | 产品本身限定为教学系统，或只请求故事与 AC、不要求任务 | 前者保留课程及已定字段／角色的正式语义，不过度抽象；后者按细化标准结束，不强制任务落地或补做架构，业务未决项仍限制相应结论 |
| X-01 | 分别独立阅读模型、架构及交付正文与必要规范引用 | 能解释模型概念／关系／规则、架构理由／责任／链路，或本批用户结果／验收／依赖及状态；无法判断处定位到正文缺口，不靠聊天、历史、样例及运行日志补全 |
